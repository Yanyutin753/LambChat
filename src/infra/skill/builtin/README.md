# 功能内嵌技能

这是随应用代码发布的只读功能参考，不属于用户技能库，不通过技能 CRUD、
市场安装或用户文件读取。用户同名技能不能替换这里的内容。

## 接入一个功能

1. 在本目录增加功能目录和简短的 `SKILL.md`，说明该功能的真实工具、操作顺序、
   结果核实方式和已知限制。避免复述工具参数表或授予额外权限。
2. 在 `catalog.py` 的 `BUILTIN_FEATURE_SKILLS` 注册唯一 ID、目录和
   `required_tools`。所有声明的工具都必须在当前模型请求中可用，才加载该技能。
3. 需要额外条件时声明 `required_capabilities`，由 Agent 组装层根据服务端已校验
   的运行环境提供能力集合；不要直接采用用户消息中的开关。工具自身仍须独立鉴权。
4. 存在平台差异时配置 `platform_files` 和未知平台说明。平台值仅用于查白名单，
   不可拼接为文件路径。无平台差异的功能仅需 `SKILL.md`。
5. 添加正反向测试：工具齐全、工具被撤销、能力未开启、重复请求，以及主/子 Agent
   实际请求。无需为新功能增加另一套中间件、用户设置或数据库记录。

## 运行契约

- `EmbeddedFeatureSkillsMiddleware` 在每次模型调用时按实际工具集合筛选；顺序遵循
  代码目录注册顺序，不依赖目录扫描顺序、时间或设备 ID。
- 使用标记为 `embedded_feature_skill` 的临时上下文消息，不改 `system_message`、
  原始用户消息、checkpoint 或用户技能设置。只有名称和内部布尔标记同时匹配才清理旧注入。
- 主 Agent、普通子 Agent、持续子 Agent 共用机制；加载位置在上下文压缩之后，
  防止技能进入会话摘要和历史归档。新增 Agent 入口也必须遵守该顺序。
- 注册表和 Markdown 都是应用代码，修改后经测试和发布生效；不存在用户编辑 API。
- 内嵌技能帮助模型使用功能，不代替权限校验、设备授权、暂停和取消等程序约束。

目前接入 `computer-use`；其他功能按需注册，避免把无关说明永久加入每次请求。
