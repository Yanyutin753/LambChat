# 可信设备远程执行与服务器失陷隔离

状态：设计待用户审阅；不是已实现功能。用户已选择控制权只留在可信设备、首次配对后无需逐条本机确认。

## 目标与用户体验

用户在对话中显式选择电脑。对话可显示在云端，代码沙箱可选择本地或云端，但涉及电脑控制、本机 shell、文件读取写入及上传下载的 Agent 执行在选中的可信设备上完成。LambChat 平台服务器负责在线发现、限流和密文转发，不获得发起电脑操作的能力。

首次使用时在可信设备间配对一次，显示设备名和密钥指纹供核对。之后从已配对的客户端发起任务，无需逐条本机弹窗。离线、密钥不匹配、任务过期或撤销时明确失败，不换机、不降级到旧明文指令协议。旧账户登录和 PAT 仅用于平台连接，不等于电脑控制授权。

成功标准不是“没有测试报错”，而是恶意平台服务器持有全部数据库、Redis、平台 JWT/PAT 与 HTTPS 私钥时，仍不能发起新电脑任务、篡改执行中任务、增加可信控制端、读取私有控制流，或通过旧协议和更新渠道取得执行权。

## 威胁边界

攻击者可修改平台 API、SSE/WS 帧、机器列表、账户和角色、服务器返回的模型配置、历史消息、工具结果、附件下载地址及更新清单；可丢弃、延迟、复制、重排流量。平台的用户身份、机器 ID、版本号、confirm_policy 和 approved 字段均不能作为本机授权依据。

假设已安装的原生应用、可信设备操作系统、本地密钥存储、独立软件发布签名密钥和用户直接选定的模型服务没有失陷。平台被攻破不能同时等同于这些独立信任根被攻破。平台仍能阻断连接、删除云端对话副本和观察连接时间/大小；这是可用性与元数据限制，不能宣称全无影响。

已授权任务也会遇到第三方网页、文件中的提示注入。端到端认证不能使模型决策天然安全；需保留原有执行权限、工作区保护、用户可见任务和停止机制，并单独验证提示注入影响。不能把“任务来自可信设备”说成“任务内所有模型行为都安全”。

## 当前代码与必须替换的边界

- `client/lambchat_sandbox/daemon.py::_process_call` 当前收到服务器 `tool_call` 即执行。服务器确认无法抵御服务器失陷。
- `src/infra/sandbox/relay/dispatch.py` 当前由服务端构造并转发 exec/fs/CUA 指令；机器与用户绑定能隔离普通账户，但不能限制被控制的服务端。
- `src/infra/tool/computer_use_tool.py` 当前属于服务端 Agent。只给它生成的指令增加客户端自动签名，会把客户端变成攻击者的签名代理。
- `src/agents/core/base.py`、现有 LLM factory/Presenter 依赖服务端配置、存储及追踪；不能直接把整套后端塞进 daemon，或继续让设备 Agent 信任平台模型代理。
- Tauri 使用包内 `frontendDist`；新控制能力仅向包内可信 UI 开放，禁止远端网页/iframe 调用配对、签名或执行 IPC。
- 桌面 updater 已有固定发布公钥，但独立 CLI daemon 自更新目前允许缺少 digest，digest 也不是发布签名。最终方案须补齐独立签名验证及防降级。

## 架构决策

选择“可信设备运行 Agent + 双端认证的加密转发”。保留平台已有云端 Agent 用于纯云端任务；它不能通过旧工具入口操作用户电脑。拒绝两个替代方案：逐条本机确认不符合用户体验要求；服务器工具指令自动签名不能实现失陷隔离。

控制端为已安装的原生客户端，执行端为显式选择电脑上的 daemon。可信端只接受用户在包内 UI 创建的任务，不接受平台 API 生成的待签名 shell/CUA 指令。两端也可以在同一电脑上，使用同一授权边界的本地 IPC。

设备 Agent 只接受已认证任务及本地配置，直接连接用户在本机配置的独立模型 endpoint。模型 API key 保存在本机，平台只持有可选显示信息，不能提供运行时 endpoint/系统提示词/工具插件覆盖。配置不足时引导用户配置，禁止静默退回平台代理。

第一条可交付执行路径必须同时覆盖 CUA、shell 和本机文件工具，及现有 Fast/Search Agent 任务所需的消息、工具循环、停止、错误与流式展示。复用现有工具执行器、CUA runtime 和消息事件定义；独立的设备运行边界不导入依赖 MongoDB/Redis/平台 settings 的后端单例。仅可复用已证明独立的纯逻辑。不能把一个孤立加密 helper 当作完整方案发布。

代码沙箱仍可选云端：由可信设备 Agent 使用本机已授权的独立沙箱 provider 配置连接该 provider。平台失陷时不能通过改变 provider 配置转为本机 shell，也不能用伪造云端工具结果驱动本机。缺少设备侧 provider 支持时明确显示尚不支持，不声称云端选择已完成。

## 配对与密钥管理

每台可信设备生成独立身份密钥；私钥仅保存于本机系统凭据库，无法使用凭据库时采用严格本用户权限文件。Windows ACL 在写密钥内容之前生效，权限设置失败停止配对。平台不得接收私钥。重装、恢复与密钥丢失必须重新配对，不能从平台恢复控制身份。

配对使用标准协议/密码库，采用双向认证 TLS 1.3，关闭 0-RTT。平台只转发 TLS 密文；不自制加密、MAC 或密钥协商。设备证书的固定信任根来自首次配对核对，而非平台下发的 CA。单纯固定平台 TLS 公钥不符合目标。

首次配对通过包内 UI 出示 QR/指纹，在另一可信设备明确核对并确认后保存对方身份和角色。配对消息绑定双方密钥、双方设备标识、短时有效期和一次性随机挑战；服务器替换密钥不能完成原配对。已配对设备的公钥变更硬拒绝。新控制端须由已信任的控制端授权或在执行电脑本地重新配对，服务器管理员、账号重置与服务器 2FA 不能绕过。

信任记录与撤销状态保存在执行设备，控制连接每次使用本地记录校验。权限可在本机撤销，立即关闭关联会话、取消尚未执行任务并拒绝后续请求。执行中的 shell 按现有进程树终止机制取消，已发生的操作不能假装回滚。

## 控制流与任务状态

1. 用户在可信客户端选择固定设备身份并提交任务；原生层确认来自包内 UI、确定本地权限与运行配置，不签名平台下发的任意调用。
2. 客户端与目标 daemon 经平台中继建立双向认证 TLS，双方检验已配对身份。平台账号/relay token 仅控制转发配额，不能授予本机权限。
3. 任务请求包含协议版本、控制端/执行端身份、对话 ID、唯一 task ID、有效期、用户任务文本、固定附件内容摘要及所选代码沙箱。接收端严格 schema、长度、类型、到期和权限检查，不接受 shell/tool_call 兼容入口。
4. 执行端在本地 SQLite 原子记录 task ID 和请求摘要后启动，重复请求只返回已有状态；同 ID 不同内容拒绝。去重跨重启持久化，避免断线重试导致重复写入或点击。
5. 本机 Agent 调用本地执行器和 CUA runtime，并通过认证加密连接回传现有消息/工具事件。对话历史的权威运行状态与索引留在设备本地，平台副本不能覆盖、续跑或改写系统提示。
6. 暂停、继续、停止、附件传输及修改任务同样只允许已认证控制端；重连检查本地撤销、任务状态和期限，不能仅凭平台 session_id 接管。
7. 平台连接断开时不新增任务或自动续期；已经认证并持久化的任务可按用户明确选定的运行策略完成，结果留在本机，恢复认证连接后读取。设备离线时控制端明确报错，不切换机器。

平台 relay 仅处理有界密文块，限制帧大小、每连接缓存、频率和并发；不能把平台传入的 URL、文件路径、命令或 app 标识当成本地指令。传输损坏、截断、重放或重新排序由 TLS 和应用任务去重检测，异常关闭连接，不转为明文。

## 对话、附件与隐私

电脑控制输入、截图、AX 树、文件与结果在可信端加密通道内传输。云端可保存密文；用户可明确把选定结果同步为普通云端消息，但须说明这种副本对平台可见，且永不作为新电脑任务的授权输入。

本机 Agent 不从平台历史、记忆、技能、MCP 配置或工具回复自动恢复执行上下文。设备端权威历史缺失时显示无法恢复，不把可篡改的云端副本当作可信上下文。附件需由控制端原生层读取、确定长度和摘要，并在认证通道中传输；不根据服务器给的下载 URL 把其内容当作用户已授权附件。

现有 CUA 私有截图路由与清理隔离继续适用于平台上已存的旧数据，并执行已有迁移与删除回归。端到端模式不把原始截图上传这些平台存储路径。日志只记录脱敏身份摘要、任务/事件 ID、状态和耗时，不能记录私钥、PAT、用户密码、shell 文本、AX 内容或文件内容。

## 原生 UI、更新与迁移

保留现有机器选择器与五语 i18n；设备名只是显示字段，身份由已配对密钥确定。显示已配对/未配对/离线/撤销状态，可信运行入口与纯云端任务清晰可辨。键盘、移动宽度、深浅色和空错加载状态遵循 DESIGN.md/PRODUCT.md。

服务器提供的普通 Web 页面不能获得“平台失陷也安全”的控制保证，因为攻击者可修改页面脚本。首个安全入口使用包内原生客户端。移动原生客户端需要同等本机密钥、TLS 和可信 UI 边界才能宣称支持；普通 Web/PWA 不自动授予控制权。服务器返回的 HTML、markdown、iframe 和工具输出不得触发原生控制 IPC，且不得在包内 UI 执行远端脚本。

执行设备同时接受旧 tool_call 等于保留绕过路径。因此安全模式必须拒绝全部未认证的旧 exec/fs/CUA、平台批准和流式上传入口；不能只关闭 CUA。旧客户端明确提示升级和重新配对；不得把新配对伪装成旧 PAT 自动配对。连接发现仍可使用平台 PAT，但它不再授予执行权限。

所有桌面、Linux、自更新 daemon 安装链路验证独立发布签名，公钥固定在应用内，拒绝未签名、签名错误、错误架构、版本降级与平台可篡改的脚本安装。服务器不能轮换信任公钥或通过版本升级清空本地信任记录。轮换/恢复仅由现有发布签名或用户本机明确操作授权。签名私钥不得放在生产服务器。2FA 属于后续账户保护，不能替代设备密钥与本机授权。

## 验收与交付门禁

必须同时完成并取得以下证据后，才声明达到服务器失陷隔离：

- 恶意 relay 集成测试：直接注入 exec/fs/CUA、伪造 JWT/PAT/角色/批准、改变目标设备、公钥、provider、历史消息和更新资产，证明无本机执行、无隐私返回。
- 标准 TLS 双端认证握手测试及真机验证：未知/替换/已撤销身份拒绝；没有信任根时失败；禁用 0-RTT 与旧明文执行路径。
- 重放、重复 task ID 内容变化、到期、重启去重、断线重连、取消与撤销竞态测试；副作用不重复，撤销立即生效。
- 真实设备 Agent 用独立模型 endpoint 完成多轮 CUA、exec、文件读写与所选代码沙箱任务，云端对话展示流式结果；平台不能替换模型配置或本地权威上下文。
- 双设备配对一次后连续操作无需逐条本机弹窗；macOS 与 Windows 分别验证 allow/deny 配对、目标机不误切、断线、恢复、撤销及凭据 ACL。
- 敏感截图、AX 密码字段、文件传输、日志与云端副本检查；上传/下载大文件及压力测试仍通过。
- 确认恶意网页/iframe/markdown 不能调用 native IPC；包内脚本只来自签名应用。安全模式的普通 Web/未实现的移动入口必须明确拒绝，不能虚假显示受保护。
- 更新全平台验证固定签名、资产架构、升级/降级策略与信任记录保留。缺签名 CLI daemon 不得自替换。
- 全量后端/前端测试、lint、类型、build，真实本地 sandbox E2E 与 stress；develop CI、staging 真实对话、main CI、生产回归；最终安装包 macOS/Windows 真机检查后才发布 latest.json。

先完成现有 TLS、机器选择、凭据/PAT/JWT 修复的独立验证；这些可以形成独立 PR，但不能把其发布描述写成“已实现服务器无控制权”。新的端到端模式、设备 Agent 和兼容拒绝必须作为完整能力交付，验收缺一项即保持未完成状态。
