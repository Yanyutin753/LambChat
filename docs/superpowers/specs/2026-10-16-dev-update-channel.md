# LambChat 可选测试版更新通道

日期：2026-10-16
状态：用户已确认，2026-10-16 按方案直接实施。

## 已确认的目标

默认用户继续接收正式版。用户主动选择测试版通道后，可以检查、下载和安装已通过 CI 的 dev release。测试版发布不再等待 Windows/macOS 人工聊天界面抽检；未完成的实机验证写入 Release 说明。完整 CI、原生打包冒烟、签名及下载完整性校验继续保留。

## 现状与必须解决的问题

- `/api/version` 只读取 GitHub Latest；下载代理已支持 `?tag=` 精确锁定版本。
- macOS/Windows 使用 Tauri updater；Linux 使用 deb/rpm 下载安装；Android 使用 APK 下载与系统安装器；iOS 目前只打开发布页面。
- dev.2 各端运行时版本都是 `2.15.2`，没有 dev 构建身份。只显示测试版资产无法实现可靠版本比较。
- 工作流禁止向 dev release 发布稳定 `latest.json`。这个隔离继续保留，新增测试通道清单。

## 拟实施设计

### 1. 一个设备级设置

在现有个人偏好“检查更新”附近增加“更新通道”：正式版（默认）/ 测试版。使用现有设置样式，同步五种语言。下载页提供相同选择，默认正式版。

偏好保存在当前设备，不跟账号跨设备同步，避免另一台生产设备意外切换通道。切换后取消旧检查结果的生效资格，清除旧的待安装目标；正在下载或安装时禁止切换，避免跨通道包被误安装。

### 2. 明确的构建身份与版本顺序

CI 将不可变的完整 release tag 注入 Web bundle 和桌面原生构建，例如 `2.15.2-dev.3`。平台安装版本仍遵守既有数字核心版本和 Android/iOS 构建号规则。

所有更新比较使用完整身份：`dev.2 < dev.3 < 正式版`，数字序号按数值比较（dev.10 高于 dev.9）。同一版本不重复更新，不允许自动降级。测试通道包含通过发布门禁的 dev 及正式版，选择其中最高版本；切回正式通道后，如果当前 dev 的核心版本高于最新正式版，则等待未来正式版，不自动覆盖安装旧版。

旧 dev.2 没有新通道代码和完整构建身份，不能靠服务端新增清单可靠补齐。首次需要手动安装支持通道的新包；此后 dev 到 dev、dev 到正式版走正常更新流程。界面和发布说明明确提示这一次迁移。

### 3. 复用现有更新及下载链路

后端版本查询增加严格枚举 `channel=stable|dev`，缺省 stable。缓存按通道隔离；GitHub draft 和未完成发布门禁的包不进入可更新列表。版本、资产、发布时间和 Release Notes 必须来自同一个 release。

macOS/Windows 使用隔离的测试通道清单，继续经过原生 updater 验签。Linux 和 Android 复用现有安装链路，所有下载 URL 绑定选定 tag。iOS 保留当前发布页下载能力，不承诺未实现的自动安装。

通道切换不能让旧请求、旧缓存、旧下载结果污染新的目标；失败应显示检查失败，不能提示“已是最新”。

### 4. 发布门禁与文档

dev release 在完整 CI、全部原生产物和签名校验通过后发布测试通道清单，仍标记 GitHub Pre-release，保持 `make_latest=false`。稳定 `latest.json` 及 GitHub Latest 继续只提供正式版。

更新 AGENTS.md、CLIENT.md 及发布说明，明确：测试版允许缺少人工桌面抽检，正式版仍保留既有门禁；测试版已知问题如 Linux 代理异常必须披露。签名校验或 CI 失败的包不发布更新清单。

## 覆盖范围

后端 GitHub release 查询和缓存、版本 API/比较测试；客户端版本身份、偏好 UI、更新 hooks、下载页及五语文案；Tauri 更新配置/原生版本比较；Linux/Android 资产 URL；CI 完整身份注入、测试清单生成/发布；发布规则和客户端文档。

不增加依赖，不改聊天或沙箱执行代码，不改变系统代理，不自动降级或修改旧 dev.2 tag。

## 验收

1. 默认正式通道完全忽略 dev release；主动选择测试通道后能找到可用 dev。
2. dev.2→dev.3、dev.9→dev.10、dev→同核心正式版正确；相同/更低版本无更新。
3. 缓存按通道隔离；切换期间迟到响应不改变新通道；下载/安装中不能切换。
4. 资产下载锁定 tag，旧版本检查结果不会下载到新版本包；签名与大小校验保留。
5. 缺少平台资产、签名、CI 失败的 dev 不成为更新目标；GitHub Latest 和稳定清单保持隔离。
6. 按共享验证锁串行执行定向红绿测试，全部改动完成后执行最终测试/lint/build；CI 构建新测试包并验证清单与下载。未实际操作的桌面更新安装明确标记未验证。
