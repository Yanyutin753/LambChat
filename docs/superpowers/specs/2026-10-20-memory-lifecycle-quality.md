# 记忆全生命周期质量与效率验收

用户目标：通过真实多轮 LLM 对话反复发现、修复和复测问题，改善通用、多用户记忆系统的准确性及效率。

## 范围与约束

- 沿用现有 retain、Phase 1、compaction、reflection、index、recall、管理 API；覆盖全部入口，保留旧数据和 checkpoint 兼容。
- 当前本地分支开发，不创建 worktree，不提交、推送或部署；保留其他对话的未提交改动。
- 所有测试及真实模型验收使用 `scripts/run_validation.py`，非阻塞取锁，单 worker；占用时不重试、不排队。
- 用户回看使用 `desktop_dev` 下明确命名的新验收对话；隔离性测试使用独立测试用户和项目，禁止读取、修改原有用户数据。
- 凭据、原始运行日志和真实模型结果存仓库外私有目录。每批付费调用绑定源码哈希、固定用例和独占启动标记；不重放已开始的批次，源码变化后停止新增调用。

## 必须证明的行为

1. **记准**：区分相似实体、数量、单位和否定；修改既有事实时保留仍有效的细节；不能把未确认的助手建议当用户事实。
2. **记全**：跨多轮积累的事实可被提取；长正文尾部事实不因压缩截断丢失；召回能定位并读取授权原始来源。
3. **用对**：新会话可召回，明确纠正优先于旧值，历史时间问题仍能定位旧值；未知信息诚实返回未知。
4. **隔离**：用户、项目和个人偏好归属正确；同名事实不得跨用户/项目污染；开关关闭后停止自动提取和模型注入。
5. **通用**：至少覆盖 zh/en/ja/ko/ru；覆盖工作、学习、日常偏好和业务事实；不依赖中文专用字符串或单一模型来修复通用语义问题。
6. **效率**：相同内容重复保存不重复 embedding、存储和失效通知；无变化的提取/整理不重复付费；新增轮次保留必要上下文并减少旧历史重送。
7. **可恢复**：并发认领、超时、取消、重启、存储失败和索引失败不造成陈旧写覆盖、假成功或不受控重复调用；删除不会被旧后台任务重新写回。

## 真实评测

固定用例：`tests/fixtures/memory_lifecycle/v1.json`。冻结题目、预期、源码、模型和配置后再发请求。回答正确性、记忆正文、scope、source refs、调用次数、token 完整性及时间分别记录，不能只凭回答声称“记住了”。

- 基线 → 失败归因 → 定向红测试 → 最小修复 → 相关回归 → 新批次真实复测。
- 真实 Agent 聊天、后台提取、整理及反馈反思分项验收；定向调度不得冒充真实空闲窗口验收。
- 初次、续聊、新会话、完全重复输入分开；主对话、提取、整理、反思、embedding、rerank 的消耗分开。
- 缺失费用/token 标为未知。未执行、被锁阻塞和缺少环境的场景明确记为未验证，不能计为通过。
- 发现失败保留原题及结果，不降低要求、不删除失败案例；新用例只能追加版本，不改旧批次答案。

## 优化顺序

先保护写入及来源、修正相关性排序；再用内容版本跳过重复工作、减少不必要正文读取；根据真实失败决定记忆拆分、增量提取和整理候选范围。语义判断保留模型能力，身份及所有权检查由服务端保证。

## 完成边界

必须有当前源码对应的定向测试、记忆相关完整回归、真实多轮生命周期结果和效率对照。有限场景通过只能证明这些场景；不能承诺所有用户、语言、供应商及无限历史都不会出错。剩余明确需求未验证时，整个目标保持进行中。

## 用户追加：单用户至少半年记忆量

- 以连续 180 天为时间跨度，在独立私有测试库按单用户 1,000 / 10,000 / 50,000 条逐级加载；这是轻、中、重使用强度的模拟档位，不声称半年一定产生某个条目数。
- 分布包含个人偏好、多个项目、业务事实、参考资料、纠正与生效日期、重复与相似实体、长正文，以及其他用户/项目的干扰。关键旧事实埋在半年前，不能只验证最近记录。
- 使用实际 Mongo 检索/索引/正文路径，记录数据量、索引/存储体积、召回正确性、跨作用域泄漏、冷/热耗时及内存/正文读取规模。确定性向量只能证明候选检索与排序的工程行为，不能冒充真实 embedding 的语义质量。
- 保持导航、候选数和最终模型上下文有界；不能将 50,000 条正文全部塞进提示词。真实 LLM 在大库背景下的回答需要另列证据，与纯存储/检索压测区分。
- 当前源码已发现风险：Mongo 余弦兜底仅扫描最近 min(limit*3,100) 条，旧语义相关事实可能无法进入候选。已准备半年前事实被 1,200 条近期噪声覆盖的回归，尚未运行；活跃付费批次期间不改其冻结源码。

## 当前生命周期审查与优先级

以下根据本地实现及本轮留存证据整理；不是生产效果保证。

| 环节 | 当前行为 | 发现与下一步 |
| --- | --- | --- |
| 会话内记忆 | 主 Agent 可调用 retain/recall/delete | 已限制模糊相似匹配覆盖不同完整事实；明确 ID 的授权更新保留。Agent 生成记录与用户手工记录的来源仍需区分，避免自动数据永久享有 manual 保护。 |
| 空闲提取 | 扫描空闲会话、按会话认领租约，单次模型输出正文和索引字段 | 整段聊天只有一个 context；个人偏好和项目事实可能混存。优先改成一次调用输出多条、分别确定作用域，兼容旧输出，并在写入前校验整个结构。 |
| 存储 | Mongo 元数据、可选外置正文、可选向量索引、失效广播 | 已保护整理时的最终条件写与正文暂存，防止并发人工编辑被旧任务覆盖。管理 API 创建/编辑/导入已接入向量写穿；正文更新但 embedding 失败会清除旧向量。仍需完善失败及并发一致性。 |
| 导航与召回 | 元数据索引、关键词/向量混合检索、可选重排和正文读取 | 导航已有元数据投影，不重复优化。已修复最终排序覆盖混合检索及重排结果；管理 API 编辑时应保留重建 index_label 所需的旧字段。 |
| 整理合并 | 数量阈值、冷却期、Redis 锁；读取正文后模型更新/删除 | 已拒绝根据截断正文做破坏性修改。效率重点是成功后保存内容版本，未变化不再付费；正文批量读取；保留合并来源；长运行租约续期及易主后停止写入。 |
| 反馈反思 | 从差评/失败蒸馏固定结构教训，配额与处理标记去重 | 保留现有信号筛选和固定 schema；需要真实纠错前后行为对照，不能只验证生成了一条教训。 |
| 遗忘 | 删除正文/行/向量并广播失效 | 还需证明旧提取和旧整理任务不会将删除内容重新引入，不能仅以删除 API 返回成功验收。 |

效率优化顺序：先修作用域及索引一致性，再做未变化跳过与批量读取，最后评估带上下文的增量提取。已实现提取成功输入指纹和部分写入的计划续跑，定向 74 项通过；真实持久化恢复与费用对照待验证。直接只取最后一轮会丢失旧事实和更正对象，不能用来换取更低 token 数。

### 下一项半年容量缺口：大库恢复

当前导出可流式生成整个库，但管理面板一次提交整个导入文件，后端每请求只接受 1,000 条及 200 万正文字符。因此 5 万条库尚不能通过当前面板完整恢复。下一步应以受限顺序批次恢复，保留导出 ID 的幂等性和失败时的真实已写数量，不直接放大单请求上限；同时完成全文件结构/截断预检。此项尚未实现或验收。

### 大库恢复实现约束

沿用现有导入端点，增加只校验模式：返回当前每批条数、每条正文和总正文上限，不写库、不生成向量、不失效缓存。前端先按服务端上限切批并预检所有批次，全部通过后顺序写入。保留导出的 ID；缺少 ID 的记录在同一次操作内只生成一次 ID。不得并行发送恢复请求或在网络错误后偷偷重放。

错误结果区分已确认完成的批次与当前未确认批次，不假装回滚或计为全成功。面板应刷新已完成结果，失败文案同时覆盖五种语言。跨批次不提供原子事务保证，预检后的权限/存储变化仍可能产生部分完成，须明确呈现；同一导出备份可按稳定 ID 重试。

### 大库恢复验收结果（本地、无模型调用）

已实现现有导入端点的只校验模式和面板受限顺序恢复。按当前服务端上限分批，全部批次通过预检后才开始写入；跨批次不承诺原子事务，未确认写入不会自动重放。导出 ID 保持不变；没有 ID 的自定义文件在单次操作内固定生成 ID，跨次重试须核对结果。

- 真实 MongoDB + FastAPI ASGI HTTP 路由：5 万条按 50 批恢复；预检阶段没有记录落库或 embedding 调用；重试已完成的 1,000 条只覆盖原 ID，总数仍为 5 万。完整导出后，全部 ID 与正文逐条一致，包含长正文尾部，另一用户记录未变化。整个测试约 14.39 秒，包含准备/预检/写入/导出/清理，不是生产 SLA，也未证明启用真实 embedding 后的恢复耗时。
- 前端 7 个文件、21 项测试通过，覆盖 5 万条顺序发送、所有预检先于写入、迟到的无效/截断记录、权限拒绝、丢失响应、不自动重放、Unicode/动态预算、UUID 兼容以及进度/持久错误状态。前端类型检查退出 0。未运行最终全项目 build/lint 或本轮浏览器视觉走查。
- 后端在存储中途失败或结果不确定时仍失效缓存，避免已经写入的记忆被旧导航继续遮挡；格式校验失败则在本批任何写入之前返回。

新增并发回归还复现并修复了提取阶段的晚期认领失效：embedding 期间被接管时，最终 native 写入重新检查现有 job fence；检查存储出错会清理未提交正文并保留重试。当前记忆/管理 API/相关中间件回归为 573 passed /20 个付费用例未启用。删除抑制、未来旧会话再提取、自然调度、反思行为及最终全项目门禁仍未完成。

### 遗忘的来源截止点与并发保护（进行中）

显式删除具有来源的记录时，先以所有者与来源会话为键保存单调递增的截止时间，只保存来源 ID 和时间，不复制被删除的事实。之后该来源的旧转录不再参与自动提取；新消息可以重新确认事实，其他会话及已有的其他记忆不被删除。整理删除重复项不产生遗忘截止点。

### 正文替换的原子清理引用

真实 Mongo 的六项失败回归确认：Native 更新、管理更新与导入在新指针提交后、清理 helper 登记前中断，会失去旧正文引用；两个读取同一旧记录的写入者还会遗漏中间版本。复用现有清理任务，在同一条 Mongo 写入管线中将实际被替换的正文键及命名空间追加到内部 `_content_cleanup` 数组，再提交新指针。用户内容必须以 `$literal` 写入，不能作为 Mongo 表达式执行；导入保留该内部数组，不接收备份提供的内部字段。

周期任务先将数组引用移交持久清理队列，成功登记后按精确引用移除，不改内容 revision；并发追加不能丢失。显式删除在删主行前也移交全部数组引用。该步骤只解决已提交替换的恢复窗口，不宣称覆盖从未提交的新正文、旧启动删行或普通向量写入故障。

最初六项真实 Mongo RED 均已修复。另以 5 万条无关记录复现待清理引用的全表扫描，增加局部索引后执行计划检查最多读取 5 条文档；每轮移交全局上限为 100 个资源，并非每条记忆各 100 个。正文、标题等用户字段均经 `$literal` 写入，美元符号开头的文本不会成为 Mongo 表达式。

### 正文写入与索引提交之间的进程崩溃

长正文写入前，先在对应 Mongo 记忆行追加独立 key/token/五分钟期限。新建行仅包含私有暂存所有者，不含公开 user_id，因此不会进入用户查询；索引提交必须匹配同一个尚未过期的 token，并原子移除该标记。新建、编辑、原生 retain 与导入均使用此路径，导入内联内容也保留其他写入者的暂存引用。逻辑删除先登记所有暂存资源，并以暂存数组快照参与最终条件删除，防止丢失并发新增引用。
