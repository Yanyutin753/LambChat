# 沙箱项目与会话环境设计

## 目标

让网页沙箱和桌面本地沙箱都能承载项目，同时保证一个 Session 从创建开始只使用一个环境，避免文件、工具权限和上下文在不同沙箱之间漂移。

## 用户模型

用户只直接理解“项目”和“会话”。沙箱是项目详情中的运行环境状态，不要求用户在每次操作时手动选择。

- 网页端创建项目时，自动绑定当前可用的网页沙箱。
- 桌面端打开目录时，自动创建或绑定当前设备的本地沙箱，再创建/打开项目。
- 项目属于一个 Environment；Session 继承项目的 Environment。
- Session 创建后，`environment_id` 不可修改。更换环境必须新建 Session。

## 可见性与状态

项目不会因为沙箱离线而消失，避免用户误以为项目或历史数据丢失。

- Environment 在线：项目可进入，可创建和继续 Session。
- Environment 离线：项目和历史 Session 仍可见，显示“环境离线”；涉及该环境的继续/新建操作禁用，并提供连接桌面端或恢复环境的入口。
- 网页沙箱与桌面沙箱都属于同一类 Environment，只是能力和在线状态不同。
- 网页端不展示本机绝对路径；桌面端可显示本地目录名和“打开目录”操作。

## 数据关系

```text
Environment
  └── Project
        └── Session (environment_id immutable)
```

Environment 至少包含：稳定 ID、类型（web/local）、显示名称、在线状态、所属用户/设备信息和能力集合。桌面本地路径只保存在客户端的私有绑定配置中，服务端保存稳定的环境 ID 和非敏感显示信息，不保存绝对路径。

Project 增加 `environment_id`，保留现有项目名称、图标、排序和会话组织能力。现有项目迁移到默认网页环境，保证兼容。

Session 创建请求携带不可变的环境来源，由服务端校验项目与环境一致，并在后续工具/沙箱调用中使用保存的环境 ID。

## 交互流程

### 网页端

1. 项目列表展示项目名称和环境状态。
2. 创建项目默认绑定网页沙箱，不出现本地目录选择。
3. 创建 Session 自动绑定项目环境。
4. 桌面项目离线时可查看历史，创建/继续按钮禁用并提示连接桌面端。

### 桌面端

1. “打开目录/创建项目”使用原生目录选择器。
2. 客户端在本地绑定目录与环境 ID，并向服务端注册/更新本地环境在线状态。
3. 当前设备的本地环境在线时，项目可创建和继续 Session。
4. 目录不存在或 daemon 断开时，项目保留但显示离线。

## 安全边界

- 服务端不接收或信任客户端传入的任意绝对路径。
- 本地目录只能通过 Tauri 原生选择器绑定。
- 本地执行继续复用现有 daemon 的 owner、路径白名单和能力校验。
- 服务端校验当前用户、项目、环境和 Session 的归属关系。

## 实现范围

第一阶段只实现一个网页环境类型和一个当前设备本地环境类型：环境注册/心跳、项目环境绑定、不可变 Session 环境、网页与桌面状态展示、离线禁用态。暂不实现跨设备迁移、Session 环境复制或多目录挂载。

## 验证

- 后端：项目/环境/Session API 与权限、迁移兼容、离线状态测试。
- 前端：项目列表状态、创建流程、离线禁用和五语 locale 测试。
- 桌面端：目录绑定持久化、daemon 在线/离线翻转和路径安全测试。
