# 工作区隔离、并发修改与恢复

状态：实施中，尚未完成最终验收。2026-10-27。

## 2026-10-27 实施收敛与能力边界

用户批准先复用持久化工作区，不再因项目归属变化而复制目录。以下结论替代下文较重的自动迁移/逐文件云端上传草案：

- 项目变更只有元数据更新；既有会话绝不重新套用项目的目录默认值。新会话仍可继承项目默认位置。
- 当前绑定继续由 session.agent_options 承载；替换前把原绑定写入独立 workspace_locations 集合，再以原 agent_options 做条件更新。位置记录只是可找回来源，不是物理迁移成功凭证。
- 客户端可从历史位置重新选择目录；不会自动复制、删除或清空任何源目录。跨机器的文件搬运不伪装成一个普通切换。
- 云端复用当前 SDK 原生卷。只有经配置启用、实际挂载核验的平台才使用新卷；旧环境保持原路径，禁止用空卷遮住旧文件。恢复运行环境时验证同一个已登记卷，不新造同名卷冒充旧数据。
- SDK 接口存在不代表服务可用。E2B 卷当前私测且不支持可靠 flock，Daytona 卷为 FUSE，Cube 依赖插件；共享文件的原子语义必须单独验证，不能跨平台直接宣称等价。
- 暂停失败不得退化成 kill；重连异常不得自动覆盖绑定；同用户其他沙箱不得因为重复清理而被删除。
- 删除此前未接入的逐文件 S3 下载/再上传备份实现。结构化修改的执行端历史与独立灾备是两件事；前者不能宣称可从卷丢失中恢复。restic 是后续独立备份候选，尚无安全的专用仓库凭据配置，不能写成已接入。
- 本轮不自动部署、不发布客户端。最终结论以当前代码的统一验证和真实环境证据为准。

下文保留最初需求与研究依据；未在本节落地的管理式 worktree 创建、跨机器传输编排、通用会话通信和独立灾备不视为已经实现。



## 用户已明确的要求

取消整目录、整轮排队。不同会话并行；共享文件通过短时原子锁、修改归属与会话通信协调。云端网页任务与本地客户端任务均支持 worktree，避免覆盖后无法找回。

本文讨论 LambChat 产品功能，不是在当前开发仓库创建 worktree。

## 建议的统一行为

- 执行位置与工作区方式分开记录：云端或指定本地机器、独立或共享。恢复和续跑不能静默换机器或执行位置。
- Git 项目支持受管理的独立 worktree，聊天与目录稳定绑定。已有会话不自动迁移；原目录未提交内容需要显式快照和应用，不能假定 Git 自动复制。
- 非 Git 项目使用独立会话目录和文件历史，不自动初始化 Git。结果显式交付回原目录，不能整目录静默覆盖。
- worktree 提供文件隔离，持久化快照负责恢复。云端恢复数据必须存到沙箱之外；本地存到受管理工作区之外。worktree 不是完整进程隔离，也不是备份。
- 快照记录实际覆盖范围；忽略文件、凭据、大文件、嵌套仓库不得默认全部复制或声称全部可恢复。

## 项目归属、当前位置与迁移凭证

用户补充要求：迁移过程必须有持久记录，后续 Agent 能查询最新位置。不能依靠对话文本里曾经出现的路径推断当前位置。

当前 LambChat 的 `SessionStorage.move_to_project` 只更新 `metadata.project_id`；路由另行同步 revealed_files 的项目索引，失败仅记日志。这不是实际文件迁移，不能返回文件已搬迁的结论。继续保留这种归属与位置分离，补齐索引同步失败的可恢复处理。

建议复用现有会话元数据保存当前工作区绑定，并增加 MongoDB `workspace_migrations` 集合记录真实迁移。暂不为每个普通文件再造一套数据库；文件迁移明细以持久 manifest 引用保存。

当前绑定包含稳定 workspace_id、location_revision、执行位置类型、机器或沙箱身份、工作目录和最后提交的 migration_id。相同云端路径在新沙箱中不是同一位置，必须包括环境代次。仅改变 project_id 时不修改位置版本，也不制造文件迁移记录。

迁移记录至少保存：

| 字段 | 用途 |
| --- | --- |
| migration_id / idempotency_key | 一次迁移的稳定身份，重复请求不重复搬运 |
| user_id / session_id / workspace_id | 所有者、归属与稳定工作区身份 |
| source / destination / expected_revision | 原位置、候选新位置及防止并发切换的预期版本 |
| status / timestamps / error | preparing、copying、verifying、committed、failed 的状态与失败原因 |
| manifest_ref / manifest_digest / snapshot_ref | 文件清单、校验依据及可恢复来源；记录覆盖范围与排除项 |
| actor / run_id / committed_revision | 谁发起、对应执行以及成功后的位置版本 |

迁移先保存记录与可恢复源，再复制到候选目录并逐项校验。受管理写入在切换窗口需停止或通过版本变化使迁移失败，不能一边无限变化一边声称快照一致；不引入整轮目录任务队列。复制成功不等于切换成功：只有当前位置绑定按 expected_revision 原子切换后，新位置才成为事实来源。

当前位置绑定作为提交事实：记录 migration_id 与新版本。若绑定切换后进程崩溃，恢复器依据该绑定补全迁移状态；若预期版本已变化则不提交，保留原源与候选副本。不能凭一条可能尚未同步的状态字段决定删除源目录。MongoDB、对象存储和文件系统之间不能假定存在跨系统原子事务。

每次开始、恢复或续跑时，服务端解析当前绑定，向 Agent 提供“当前位置、位置版本、上次成功迁移、旧路径查询入口”。工具调用绑定版本；旧执行不能借自动重定向把旧修改写进新位置。旧观察需重新读取验证，迁移凭证证明位置与搬迁校验，不证明文件当前内容永远没变，也不代替权限检查。

旧文件引用按稳定文件身份或 workspace_id + 相对路径解析。只有 manifest 确认的路径才能重定位，不能全局字符串替换历史消息中的绝对路径。未纳入备份的文件明确标记不可恢复。

## 共享文件提交

读取返回执行端生成的完整文件版本，绑定目标、规范化路径、存在状态和摘要。结构化编辑、写入、删除、上传及网页编辑共用提交入口。

先准备临时内容，再非阻塞获取稳定的跨进程文件锁。锁内检查预期版本、保存必要恢复内容并原子提交。不能锁被替换的目标 inode，也不能删除稳定锁文件。占用或版本不符只返回本次文件操作冲突；会话重新读取调整或继续其他工作，不进入目录队列。新文件也校验预期不存在。

提交记录绑定可信 user/session/run/call 身份及前后版本。仅在版本链匹配时归属最近修改者；外部修改标记未知。云端在实际文件所在执行环境完成校验和提交，Redis 锁不能替代远端原子操作。

普通 shell、外部 IDE 和未接入协议的进程不遵守这些锁。独立 worktree 减少影响，快照提供恢复点，但不能承诺找回每次外部写入。

## 会话通信

仅同用户、有权限且共享资源的会话可以交换协作消息。运行中在安全模型边界接收；已完成或取消的会话保存通知，不自动唤醒付费执行。消息标明来源并按低信任内容处理，不能伪装成人类指令；通知成功不意味着允许覆盖。

复用现有父子 mailbox、持久投递和事件能力，但不直接复用会生成 HumanMessage 的 steer 注入。新增工具仍需专属前端 Item 和五语文案。

## 生命周期与恢复

- 恢复先生成候选副本或差异；目标有新修改时再次校验，不直接回滚覆盖。
- 合并回项目时保留双方冲突内容，不自动提交或推送用户项目。
- 清理受管理工作区前，确认在途写入停止、恢复数据已持久化且可读取。保存失败保留目录。
- 删除聊天不递归删除用户原目录、共享目录或其他会话文件。聊天删除、工作区归档、恢复数据删除分别处理。
- 恢复清单记录所有者、原目标、版本、时间、范围与完整性；跨账号访问和恢复被拒绝。
- 取消、断线、重启、审批恢复与 Goal 续跑保持固定目标，旧调用不能向重新分配的目标写入。
- 明确展示保留期与容量限制，不静默淘汰唯一恢复副本后仍声称可恢复。

## 当前已发现的问题

1. 本地 daemon 对 exec 跳过传输依赖；不同 receipt 可以指向同一实际目录，不能以 receipt 作为锁身份。
2. StreamUploadWriter 第一帧直接截断目标，断流留下部分文件；空上传 touch 不清空已有内容。需临时文件、完整 EOF/长度校验、成功才提交。
3. 取消 asyncio.to_thread 的等待不等于终止底层进程，清理前需要真实停止确认。
4. 云端按用户复用沙箱，有共享目录、进程与环境；worktree 不代表完整沙箱隔离。
5. 云端空闲暂停统计混入本地任务，需要按固定执行目标区分。
6. Search/Team 的 selected workspace 标识和真实会话身份需分开传递；evidence clock 不能替代跨会话文件版本校验。

## 验收

先写失败测试，再实现；本地验证统一经 scripts/run_validation.py 串行执行。

- 两 worktree 同名文件并行修改互不覆盖；合并冲突保留双方。
- 共享文件过期提交失败、原内容可恢复；不同文件并行。
- 路径别名、符号链接、硬链接和目标替换不能绕过检查。
- 上传断流、缺 EOF、错误长度、超限、取消和空文件替换不损坏旧文件。
- 在备份、替换、记录、通知阶段崩溃，可判断实际状态，不重复结果未知的写入。
- 覆盖取消、审批、Goal、daemon/worker 重启、云端暂停恢复、删除和归档。
- 同用户通信可达，跨用户拒绝，闲置任务不自动执行，外部修改不错误归属。
- 实测云端沙箱销毁后的持久存储恢复，以及本地 worktree 删除后的恢复，逐字节核验。
- 旧 daemon 能力探测和降级提示；五语 UI；真实 daemon 和云端分别验收，未测不算通过。

此设计尚无实现或验收结论，不能沿用上一版本结果证明新能力。
