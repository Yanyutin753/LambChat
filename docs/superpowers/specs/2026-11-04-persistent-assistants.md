# 长期助手与持续任务

状态：功能已接通，核心路径已完成真实本地验收；最终检查及未测范围见下文。尚未部署生产。

## 产品目标

用户持续联系同一个助手，同时推进多件事、补充要求、查看结果和处理决策。
助手身份、用户可见讨论、授权任务和底层执行批次分别持久化；模型上下文不是任务数据库。
沿用 LambChat 的模型、角色、Team、工具、审批、后台执行、Goal、调度、沙箱、渠道和用量体系。

## 实现顺序与边界

1. 长期助手身份与租户隔离存储、版本更新；对接现有角色及会话。
2. 持久任务/授权与协调工具，对接现有后台执行与完成事件，不能创建第二套执行队列。
3. 可见助手与活动页面、任务控制、审批和结果，打通真实模型本地闭环。
4. 渠道订阅、主动规则与调度，群聊和记忆范围，故障恢复与费用归属。
5. 完成全部调用方、五语、文档与测试后串行最终验证，真实使用并修复，再将 PR 转为可审阅。

身份配置不包含 API 密钥，不替代实时 RBAC；私聊可读不等于允许向群里披露。
助手暂停、停止单个任务和取消未来规则是不同操作，界面说明各自影响。
任务保持原执行环境；更改助手默认环境不迁移正在运行的任务。
恢复不以重发外部写入解决不确定状态；只有真实投递成功才生成送达收据。
所有验证通过 `scripts/run_validation.py`，worker/job=1；占用即退出。
真实验收使用 `desktop_dev`，保留可回看的对话及产物，凭据和报告放仓库外。

## 实现记录

- 助手身份、版本更新、固定会话、模型/角色/Team/项目/本地目录配置，以及创建、编辑、暂停、恢复、归档和历史入口。
- 提交、入队、审批恢复、故障恢复、定时和渠道入口复查实时授权。协调助手暂停与已授权独立任务分开处理，任务继续保留原环境。
- 独立任务复用现有后台队列，记录幂等提交、来源授权、截止时间、续办轮次、恢复次数及绑定当前运行的人工验收。执行完成先进入待验收，不能直接算用户已接受。
- 默认助手私有记忆及显式项目助手共享记忆；检索、导航、提取和管理使用同一分区。作用域查询失败不降级到个人记忆；保留所有者在全局记忆管理中的备份权限。
- 通用渠道、飞书、微信绑定助手后使用独立讨论及受众记忆。网页续聊和结果投递重查当前绑定与 ACL；讨论任务继承原受众。明确的 `/task <task-id> <message>` 续办原任务，模糊引用先澄清，扩大权限或环境需要新授权。
- off / observe / auto 规则复用现有调度，支持间隔及任务完成事件、累计唤醒上限、冷却、原子去重和执行超时。observe 不调用模型，auto 的 `NO_UPDATE` 抑制本次无变化通知。
- 主会话、讨论、独立任务及显式来源的辅助调用归属同一助手账本；未知费用保留未知。完成通知分别记录持久化及传输接受情况，不表示用户已读。
- 五语助手列表、配置、任务、规则、讨论、记忆和用量入口，复用主题与权限。助手及独立任务的输入框锁定配置，避免普通聊天的历史选项改变任务环境。

实际使用发现并修复了三类问题：读取接口使用旧权限名导致入口不可用；审批重建后丢失文件观察版本导致合法编辑冲突；助手卡片及窄屏长任务描述挤压操作区。文件审批恢复只携带与工具批次、用户、会话、机器及目录绑定的原观察版本，仍由执行端比较原始版本，不降低并发写入、证据或授权要求。

模型供应商多次返回 429，全部失败历史保留；按原任务续办后完成上述闭环。任务 B 的模型报告对首轮失败类别的文字归因有偏差，原始执行日志及独立复核为准：首轮为 1 个失败、4 个错误，最终 13 项全通过。这是验收模型产物的限制，不将模型自述作为唯一通过证据。

## UI 迭代：独立助手工作区

参考 [CopilotKit OpenBot](https://www.copilotkit.ai/openbot) 的频道工作台、[CopilotKit OpenMuse](https://github.com/CopilotKit/openmuse) 的独立活动页，以及 [OpenBot](https://github.com/nightly-labs/openbot) 的助手侧栏、中央对话与按需打开的工作面板，以及 [OpenMuse](https://github.com/diggerhq/openmuse) 官网展示的主对话、主题列表和上下文面板。已查看官方交互预览、应用截图及布局组件源码；只参考信息结构，不复制代码或引入依赖。OpenMuse 存在同名项目；同时核对了 CopilotKit 版以及 open-muse.dev 指向的 diggerhq 版。

- `/assistants` 使用独立工作区外壳，左侧常驻助手导航，中央直接复用真实 ChatAppContent；不再以管理卡片和任务弹窗作为主流程。
- `/assistants/:assistantId/chat/:sessionId` 承载主对话、任务结果及讨论；首次打开仍由服务端建立稳定会话。子会话先验证所属助手，避免把其他助手的对话显示在错误的身份下。
- 任务、规则、讨论、记忆、用量提供页面入口和可回访的 URL，按权限展示；普通聊天中的快捷弹窗仍复用相同业务组件。
- 桌面支持收起侧栏；手机使用助手列表与详情两级页面，详情顶部仅保留对话/任务切换，其余功能进入菜单。沿用主题 token、按钮、菜单、分页与五语文案。
- 任务保留当前页状态分组、详情渐进展开、失败保留草稿及幂等键、真实运行 ID 取消和版本化验收；翻页请求期间保留总数，避免错误回到第一页。
- 视觉继续收敛到 OpenBot / Codex 的紧凑工作台：侧栏去掉常驻启用状态和大筛选框；任务以短标题、时间和状态呈现，完整要求仍在详情中；设置进入菜单，首页主操作与说明居中成组。
- 进一步对照 [CopilotKit OpenDots](https://www.copilotkit.ai/opendots) 的角色身份呈现和 OpenMuse 官方交互预览：列表与页头共享现有 AgentAvatar，绑定角色或团队时读取其头像与名称；无读取权限或资源不可用时保留助手自身的生成头像，不阻断工作区。仅请求当前可见助手需要的元数据，不改动历史消息身份。
- 首页、任务页及讨论/规则空状态复用已有 SceneIllustration 小羊插图；深浅主题沿用已有颜色 token，任务说明和日期保持可读对比度。没有引入新字体、图像依赖或第三方素材。

## 个人助手交互收敛（2026-11-04）

保留现有 Codex 式执行工作区，在 `/assistants` 增加 Dots 式长期助手体验。两个区域复用聊天、文件预览、后台任务与权限系统；不引入第二套执行引擎。

- 点击助手进入持续对话，不要求用户在“主对话”和“任务”之间选择模式。工作记录、渠道讨论、规则、记忆及费用集中在一个更多菜单，移除重复侧栏入口。
- 从工作记录安排工作后直接进入真实执行对话；自然语言交代工作时，现有后台工具生成的结果链接也保持在当前助手工作区。原有普通聊天链接行为保持不变。
- 工作结果旁展示当前状态及按需出现的停止、验收和返工操作。完整要求折叠保存；任务读取匹配当前会话，操作绑定当前 run/revision，加载失败及版本冲突期间禁用决策。轮询与窗口恢复刷新状态，旧读取不能覆盖新的验收。
- 助手名称可返回日常对话；空渠道列表提供开始聊天的路径。执行记录仍独立持久化，不混合不同工作的证据或渠道受众。

主要参考近期个人助手项目 [OpenDots](https://github.com/CopilotKit/OpenDots)：连续聊天、内联工作反馈和上下文中的人工决定。阅读其 `Chat.tsx`、`PageReviewCard.tsx`、`TaskActions.tsx` 后，复用 LambChat 的真实状态与审批约束，不移植其运行时或资产。

### 复杂协作验收
