# Unified Document Viewer Design

## Problem

DOCX, PDF, and PPTX previews currently use different layout and input models:

- DOCX reflows content inside a fixed synthetic `816px` by `1056px` card and
  overrides the page dimensions generated by `docx-preview`.
- PDF uses a continuous scroll surface and a dedicated top toolbar, while
  Ctrl/Command plus wheel changes zoom.
- PPTX uses the shared floating `ViewerToolbar`, but captures every wheel event
  for zoom and moves an absolute-positioned canvas by dragging.

The mismatched behavior makes switching formats feel unpredictable. Wheel and
trackpad gestures can also change zoom when the user intends to read by
scrolling.

## Goals

Create one conventional document-reader experience for valid DOCX, PDF, and
PPTX files:

- use a shared full-size canvas and the existing floating `ViewerToolbar`;
- make mouse-wheel, trackpad, and one-finger gestures scroll content;
- make toolbar buttons the only zoom controls;
- display DOCX and PDF as continuous vertical pages and PPTX as continuous
  vertical slides;
- center pages, preserve authored proportions, and use consistent gaps,
  shadows, loading treatment, and theme-aware canvas colors;
- allow horizontal and vertical scrolling after zooming;
- retain existing per-format rendering and user-facing fallback behavior.

## Non-goals

- Adding page or slide navigation controls.
- Adding rotation controls to document previews.
- Replacing `docx-preview`, `react-pdf`, or `@jvmr/pptx-to-html`.
- Making fallback text imitate pagination that cannot be recovered from the
  source format.
- Supporting wheel, Ctrl/Command-wheel, pinch, double-click, or drag-to-pan as
  alternate zoom mechanisms.

## Preview Scope Audit

Only DOCX, PDF, and PPTX join this reader because all three have fixed page or
slide geometry and benefit from continuous reading with fit-relative zoom.

Other preview types keep their existing interaction model:

- Excel is an interactive grid whose native two-axis scrolling, sticky headers,
  and sheet controls must remain independent from page zoom.
- Markdown, HTML, plain text, and source code are reflowable content and should
  adapt to the viewport instead of simulating fixed pages.
- Images, Excalidraw, Mermaid diagrams, and CAD files are two-dimensional
  canvases where direct pan and zoom remain appropriate.
- Audio and video retain native media controls.

Those previews may reuse visual tokens in later work, but they do not use the
shared paged-document frame in this change.

## Architecture

Add a small shared document-viewer frame used by DOCX, PDF, and PPTX. The frame
owns:

- the full-height, overflow-enabled canvas;
- responsive canvas padding and theme colors;
- the floating `ViewerToolbar` placement;
- fit-relative zoom state and bounded zoom actions;
- ResizeObserver-based viewport width measurement.

Each preview remains responsible for converting its source file and rendering
format-specific pages. It provides its natural content width to the frame and
renders page content at the frame's computed display scale.

The displayed percentage is fit-relative. `100%` means that the natural page or
slide width fits the available canvas width. Reset returns to this fitted view.
Zoom buttons change the fit-relative multiplier in fixed, bounded increments.

## Format Behavior

### DOCX

Enable the `docx-preview` wrapper and preserve document width, height, page
margins, pagination, headers, and footers. Remove the outer fixed synthetic
paper card and stop overriding generated page width, minimum height, and
padding. The shared frame scales the generated page group without reflowing the
document.

Mammoth, legacy DOC, and extracted-text fallbacks remain responsive reading
cards. Because they do not have reliable page geometry, they do not show the
zoom toolbar.

### PDF

Keep PDF.js continuous multi-page rendering and existing failure fallback.
Replace the format-specific top zoom toolbar with the shared floating toolbar.
Remove wheel and double-click zoom interception. Page width continues to be
derived from the fit width and current zoom multiplier.

### PPTX

Keep local browser rendering and text extraction fallback. Replace the absolute
drag canvas with the shared overflow surface. Render slides as a centered
vertical sequence whose layout dimensions track fit width and zoom, so native
scroll ranges remain correct. Remove captured wheel zoom and mouse dragging.

PPTX text fallback remains a responsive card list without zoom controls.

## Input and Responsive Behavior

- Mouse wheel and trackpad scrolling use native container scrolling.
- Ctrl/Command-wheel is not captured by the preview.
- Mobile one-finger movement uses native scrolling.
- Zoomed content may overflow horizontally and vertically.
- Desktop uses comfortable canvas padding; narrow viewports use reduced
  padding while retaining the document's aspect ratio.
- The floating toolbar remains above the safe-area inset and does not affect
  scroll layout.

## Error and Loading Behavior

Each format keeps its current conversion and rendering fallback. The shared
frame can show a centered loading overlay without changing the scroll geometry.
Fallback content is excluded from zoom behavior because it has no reliable
natural page size.

## Testing

Follow TDD with focused tests that first fail against the current behavior:

- shared frame renders the existing `ViewerToolbar`, computes fit-relative
  sizing, and exposes an overflow scroll surface;
- DOCX enables its wrapper, preserves original page width and height, and does
  not use the fixed synthetic paper card on successful rendering;
- PDF uses the shared toolbar, keeps continuous pages, and has no wheel or
  double-click zoom handler;
- PPTX uses the shared overflow surface and toolbar and has no captured wheel
  zoom or drag-to-pan handler;
- fallback branches remain available and omit invalid zoom controls.

After focused tests pass, run the relevant frontend test suite, frontend lint,
and frontend build.
