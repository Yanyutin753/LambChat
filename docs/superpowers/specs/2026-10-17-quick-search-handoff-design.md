# Quick → Search 同会话接力

用户已确认：Quick 处理直接问答，需要搜索、文件或执行能力时自动交给 Search，在原对话完成；上下文、停止、审批恢复、用量必须完整。

- Quick 的同一次模型调用可以选择内部交接动作，普通问答不增加分类调用。仅向有权使用 Search 的用户暴露交接动作。
- Quick 交接时先把本轮用户消息带稳定 ID 写入共享检查点，不写入 AI 路由工具调用。Search 继续使用同一 session/checkpointer，复用该消息 ID 避免重复，并继承附件、模型、persona、语言、工具/技能限制。交接元数据保存原附件；重启恢复先保留原检查点，再追加恢复指令。
- 同一 run/trace 顺序执行，Quick 交接时不发送 done/goal:end；Search 输出唯一最终结果。前端通过持久化 status 事件显示接手里程碑。
- agent_id 保留用户选择；agent_handoff 按 run_id 记录实际执行者及 Quick 用量。停止检查和元数据写入都受当前 run 所有权保护；审批和重启恢复选择实际执行者。
- Search 用量从 Quick 累计值开始，审批恢复优先使用审批里保存的完整累计值，避免重复加入 Quick。使用同一个模型配置，不暗中升级模型或权限。
- 不自动选择 Team，不新增全局路由系统、模型配置或独立聊天。

验收：直接回答一次调用；交接上下文/附件不丢且消息不重复；无提前完成；取消不启动或遗留 Search；审批恢复不重跑 Quick；累计 token/cache/费用正确；过期 run 和未授权目标不能执行；交接提示支持五语及历史回放。
