## 发现与优化

- 坐标双击漏传 PID：工具正确拒绝，模型自行恢复。补充参数 schema 与工具说明，坐标操作必须明确目标应用，不隐式选择前台。
- 同一模型回复的多条 GUI 调用可被并发执行，上游确认策略查询和 relay 请求的异步时序会改变到达顺序。2026-10-10 07:38:57 UTC，模型先发回车，再发输入；daemon 审计却先收到输入，随后连续收到多条回车。Writer 段落错乱，模型耗时清空重输。daemon 原本已经逐条执行，无需再加线程锁。
- 在正式 `computer_use` 工具开始异步确认查询之前，按事件循环、用户和机器排 FIFO 锁，持有到结果处理完成。保留机器绑定、每次操作的确认与截图访问控制。不同桌面仍可独立推进；取消或报错释放队列；空闲锁用弱引用回收。该锁保证同一执行进程内的调用顺序，不宣称多个服务 worker 间有全局事务。
- 单测已复现后续输入越过被阻塞的首条操作，并验证修复、桌面独立推进和取消释放。
- WPS 格式对话框由 et 进程承载，主窗口 pid 的树里能看到它，但主窗口失去焦点。模型额外枚举应用才能找到活动 pid。给 `state` 补充可选 `foreground_pid` 提示，只报告实际前台进程，不替换调用目标或放宽截屏限制；前台查询不可用时保留原树。原生校准 PASS：主窗口 pid 25352 提示前台 18568，后者返回实际「单元格格式」对话框与截图，Esc 正常关闭。

- Windows 单次 `type` 写五行中文，工具返回成功，文件 XML 却缺失一整格「显示器」，「支架」变成「架」。逐格输入题没有该缺陷。已给 Enter / Tab 后补 150ms 编辑器切换间隔，归一化 CRLF；回归测试先红后绿，真机复测 PASS：两份新工作簿各检查中文、英文、数字与公式、CRLF 四列，以及 Tab 五格一行，文件 XML 值和公式结果全部精确匹配。
- Edge 滚动追加测试：测试机安装的 PyAutoGUI Windows `_hscroll` 调用垂直 `_scroll`，且传给 Windows 的 delta 未乘 120。增加原生垂直 / 水平滚轮路径，微小正滚动量至少一格，事件兜底未指定区域时移到活动窗口中心，并拒绝同进程后台窗口。单测先红后绿；真实 Edge 位移对照与模型任务 PASS。初次启动隔离配置出现账号同步提示，改用访客窗口；不改变账号设置。滚动区域与小步观察说明同步进工具 schema / 指引。Windows 单格 delta 与方向定义见 [Microsoft mouse_event 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-mouse_event)。

- 跨程序题严格检查发现标题并未加粗，模型把 B 按钮视觉状态读错。测试机 PyAutoGUI 的 Home / End / 方向键没有扩展标记；改用现有 pywinauto 的 VirtualKeyAction，保留快捷键修饰键并在失败时释放。回归测试先红后绿；导航选区真机对照 PASS：原版相同 Ctrl+Home / Shift+End / Ctrl+B 未加粗任何正文，修复后第一段加粗、其余两段普通，文本原样保留。不能据此把原跨程序题改记 PASS；Agent 文件格式纠错复测 PASS，使用首轮失败文件副本，未改原失败记录。

- Edge 模型首轮在列表已到底时多滚一次以探测边界，触发滚动链，主页面从 0 变为 1000；模型识别后在父区域恢复 0，保留列表末尾。补充指引：通过最后一项与滚动条确认可见边界，不再追加滚轮探测；父区域移动时从列表外恢复。回归测试先红后绿，边界复测还暴露记忆范围问题，见下一项。单次大 delta 的距离仍可能被浏览器限制为一屏，增大参数不能保证等比例提速。

- 冷启动边界复测中，模型连续召回两次空记忆，再保存当前滚动位置；位置正确且无额外 GUI 输入，但违反题目工具范围，仍记 FAIL。共享记忆指引明确用户工具限制优先、GUI-only 使用当前状态、不召回或保存屏幕位置；保留项目约定的主动召回与原有事实类型，普通 / VFS 两种指南同时更新且维持 960 字符预算。回归测试先红后绿，新的一次性用户重跑同题不再调用记忆，但仍追加一次横滚。继续明确已完成目标时停止输入 / 相同观察；回归测试先红后绿。第三轮同题、同配置、新账号复测 PASS：只有一次 state 截图，无滚轮、键盘、点击、记忆调用；三个位置精确保持。启动评估前，校验专用窗口标题后用正式工具切到前台，准备操作不计入模型轨迹。前两轮 FAIL 保留：第一轮调用两次空记忆并保存临时值；第二轮 8 次 CUA / 约 8 分钟，额外小步横滚且重复截图。单次复测不能证明所有页面都会自动停止多余确认。

## 格式纠错复测与 Windows 原生类型修复

失败 XLSX 的原生副本使用 Name Box 选择汇总 A1:B1，再按一次 Ctrl+B 保存，通过全部排序 / 公式 / 格式 / 冻结校验，逐格对照只有这两个表头加粗。Ctrl+B 可用，未再改键盘实现。Search Agent + glm-5.3-flash 对另一份副本采用字体对话框纠错，25 次 CUA、无其他工具调用，最终文件全部条件通过且其他单元格内容、公式、字体、金额格式与冻结不变。这是带方法提示的定向纠错，不把原完整排序题改记 PASS。

staging 已使用完整聊天 HTTP/SSE、Search Agent、glm-5.3-flash、真实 Windows daemon 继续跑更难的 Edge 复核题。在此过程中发现并修复：

- 测试机实际 comtypes 生成的 `IUIAutomationElement.CurrentIsPassword` ABI 为 `POINTER(c_int)`，原生 false 返回整数 0。旧代码的 `is False` 拒绝了普通字段值，也令 Toggle 状态隐藏。两条读取路径统一使用保护判断，只允许精确 bool / int 类型的 false / 0；密码 true / 1、-1、未知、字符串和浮点 0 均不读取。四条新整数零用例先失败，再修复；保护分支测试继续要求完全不触碰值接口。
- 原生滚轮给共享 `ctypes.windll.user32.mouse_event` 设置无符号参数类型；测试机 PyAutoGUI 的 `_sendMouseEvent` 随后传 `c_long` 坐标，出现 `ArgumentError`。改用独立 WinDLL 函数绑定，不修改 PyAutoGUI 缓存签名。先失败的回归验证共享 argtypes / restype 不变；原来的方向、120 delta 与大步范围测试保留。
- Edge 新窗口未取得焦点时，模型重复了两次失败截图和一次容器观察，随后显式 activate 恢复。工具指南明确窗口 focused=false / screenshot.foreground_required 时先激活对应窗口，不重复同一后台截图。未自动抢焦点，也未放宽截图权限。

最新相关测试 702 passed / 3 skipped；全仓 Ruff / 格式与 Mypy 564 文件通过；修改后的全量本地沙箱 E2E 含压力段 51/51 PASS。独立审查的 Windows / 工具套件 110 passed，无阻塞项。当前单测和 E2E 结果不替代这两处原生类型修复的真机校准或冷启动模型复测。33 个本地评估账号的用户、PAT、会话、私有文件记录与测试记忆均已审计为 0；部署测试账号另行清理。
